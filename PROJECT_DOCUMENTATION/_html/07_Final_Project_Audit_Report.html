1. Audit statement

This audit reviews the RoadScan AI implementation against the objectives of the MCA project “Indian Road Damage and Pothole Detection System Using Deep Learning”. The review is a source and design audit of the repository as implemented for Tushar Ravidas Jarwal (Roll No. 19), guided by Professor Ajay Patil. It is not a certified software-security assessment and it is not a pavement-engineering validation.

Method: read the Flask application, the React routes, the API client, the about-page scope, the README, and the connection notes; compare them with the requirements in the project report; record gaps without inventing benchmark scores.

3. Findings

Finding F-01 — Dashboard video count is not computed

GET /api/dashboard/stats returns files, damages, and high from the history table. It does not split image and video. The client then assigns files to totalImages and sets totalVideos to 0. A dashboard card for videos can therefore read zero even after successful video jobs. History itself still stores type video.

Rating: minor functional defect. Recommendation: count by type in SQL and map the fields directly.

Finding F-02 — Annotated stills are served as video/mp4

The outputs route passes mimetype video/mp4 for every file name. JPEG results may rely on the browser sniffing the bytes. A strict client can fail to display a still.

Rating: minor. Recommendation: choose image/jpeg or video/mp4 from the extension.

Finding F-03 — API is not tied to the login session

Anyone who can open port 5000 can post images, read history, delete a history row, and change a repair status. CORS does not add an authentication check. For a classroom laptop this is the intended simplicity. For any shared network it is an exposure.

Rating: accepted limitation for the academic build. Recommendation: say this in the viva. Do not deploy the server on a public IP in this form.

Finding F-04 — No held-out accuracy sheet

A detector without a reported evaluation can look stronger in a demo than it is on unseen roads. compare_models.py can print counts on local images. Those counts are not a test set score.

Rating: documentation gap. Recommendation: add a one-page evaluation when a labelled sample is available, and keep the low-confidence note about best.pt.

Finding F-05 — Video recall is bounded on purpose

Stride and the 90-frame cap make the demo usable and can skip a short-lived defect. The API returns frames_processed, frames_total, and stride, so the limitation is visible.

Rating: accepted design trade-off. Recommendation: mention it whenever a video result is shown.

Finding F-06 — Upload type is enforced by decoding, not by an allow-list

A file that OpenCV cannot read is rejected. A very large video can still consume disk under uploads before the cap stops inference. There is no virus scan and no maximum byte check.

Rating: acceptable on a personal demo machine. Recommendation: add a size limit before any wider use.

Finding F-07 — Repair state machine is open

The API allows any permitted status from any other permitted status, including moving backward. The audit diagram shows the intended direction only.

Rating: minor process gap. Recommendation: reject illegal jumps if the department wants a strict workflow.

Finding F-08 — College name is not in the source

About.tsx records the student, roll number, and guide. It does not record the college. Covers in this documentation set leave a blank line so the wrong institution is not printed.

Rating: administrative. Recommendation: fill the college and university lines before binding the report.

5. Standards of description

The audit accepts the project language when it says “visual estimate”. The audit would reject any slide or sentence that states a specific mAP, a percentage of Indian roads covered, or a claim that the tool is approved for official inspection, because those statements are not supported by the repository.

6. Readiness opinion

The build is ready for an MCA final-year demonstration of a deep-learning web system, on the condition that the student: (1) starts from a machine where /api/health shows the intended weight file, (2) explains severity, risk, frame skipping, and the local login in one sentence each, (3) does not quote an accuracy number that was not measured, and (4) writes the college name on the bound cover.

The build is not ready to be exposed on the public internet or to be used as the sole basis for a repair payment.
